| Группа сущностей                                                                                                                            | Предлагаемый тип хранилища                                                              | Обоснование                                                                                                                                                                                                                         |
| ------------------------------------------------------------------------------------------------------------------------------------------- | --------------------------------------------------------------------------------------- | ----------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| **OLTP** — Счёт, Договор, Транзакция, Платёжное поручение, Обращение клиента, Согласие, График платежей, ПДН, ПСК                           | **Реляционная OLTP-БД** — PostgreSQL / Oracle                                           | Транзакционная фиксация операций, контроль целостности, управление статусами и согласованное изменение связанных данных. Для ПДН и ПСК — сохранение результатов, исходных данных и истории расчётов.                                |
| **MDM / НСИ** — Клиент, Кредитный продукт, Тариф, Дополнительная услуга, Справочник                                                         | **MDM-платформа, продуктовый каталог и сервис НСИ с реляционным хранилищем**            | «Золотая запись» клиента и устранение дублей FU/RB; согласованные описания продуктов и услуг; управление версиями тарифов; единые коды и значения справочников.                                                                     |
| **DWH** — исторические копии и агрегаты по Счёту, Договору, Транзакции, Платёжному поручению, Графику платежей, ПДН, ПСК, Обращению клиента | **Колоночная аналитическая БД в составе DWH** — например, ClickHouse                    | Аналитические запросы по большим объёмам данных, расчёт агрегатов, построение отчётности и BI-витрин. Операционные записи сохраняются в основных системах, в DWH поступают их аналитические копии.                                  |
| **Data Lakehouse** — исходные выгрузки и история изменений Транзакций, Платёжных поручений, Договоров, Графиков платежей, ПДН и ПСК         | **Опционально: Lakehouse** — Apache Iceberg на объектном хранилище с обработкой в Spark | Хранение больших наборов исходных данных для сверки, повторной обработки и исследования. Iceberg поддерживает снимки состояния таблиц и атомарное применение изменений. Необходимость определяется объёмами и сценариями обработки. |
| **Объектное хранилище** — файловые представления Договора, Согласия, Графика платежей; вложения Обращения клиента при их наличии            | **Object Store с S3 API** — например, Ceph Object Gateway                               | Хранение подписанных файлов, сканов и вложений. В операционной БД остаются ссылки, метаданные и связь файлов с бизнес-сущностью. Поддержка версий объектов позволяет сохранять разные файловые представления.                       |
| **Графовая БД** — представление связей между Клиентом, Счётом, Договором и Транзакцией                                                      | **Опционально: Neo4j**                                                                  | Обход связей на несколько шагов, поиск цепочек операций и связанных клиентов. Выделяется при наличии специализированных сценариев анализа связей; обычные отношения между сущностями остаются в основной модели.                    |
| **Поисковый движок** — поисковые представления Обращения клиента, Клиента и текстов Договоров                                               | **Опционально: OpenSearch / Elasticsearch**                                             | Полнотекстовый поиск по обращениям и договорам, поиск клиентских записей, поиск фраз и неточных совпадений. Хранится производный индекс, восстанавливаемый из основных данных.                                                      |
